# 设计记录

## S1 模块边界

- `ingest.py`：逐行读取 JSONL，记录物理行号、输入文件 SHA-256、空白行数和 JSON 解析错误。
- `validate.py`：验证单条记录的结构规则，不访问其他记录，不判断回答质量。
- `__main__.py`：提供 `check` CLI，汇总读取和验证结果，写出 `accepted.jsonl`、`rejected.jsonl`、`summary.json`。

## S1 关键取舍

读取和结构验证被分开，原因是坏 JSON 行甚至无法进入结构验证；它们只能由读取层用原始文本和行号隔离。结构验证只处理已经成功解析为 JSON 对象的记录。

当前不做 sample_id 唯一性检查。ID 冲突需要看完整输入集合，属于 S2 清洗与去重阶段；S1 的目标是判断单条记录是否符合基本结构。

未知字段暂时不会进入输出训练载荷，因为训练载荷还未实现。后续阶段需要决定是否在元数据中保留未知字段警告。

## 哈希

S1 只计算输入文件 SHA-256，用于定位输入版本。内容哈希会在 S2 规范化与去重阶段实现，因为它依赖清洗、脱敏和稳定序列化规则。

## 后续设计点

- S2：NFC 规范化、邮箱/手机号模拟脱敏、内容哈希、精确去重、ID 冲突隔离。
- S3：SQLite 表结构、事务写入、重复运行不翻倍。
- S4：泄漏组连通分量、稳定划分和导出。
- S5：人工标签 CSV 校验、审核通过导出和质量报告。
